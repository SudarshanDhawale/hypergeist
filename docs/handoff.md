## 2. Decisions already made

- Product: retro "stack" environment (HyperCard reborn), category Resurrection. Name HyperGeist. Look: 1-bit classic Mac style (`.kiro/steering/design-language.md`, auto-included for UI work). The Ghost accent color is AI-only; there is no orange in the UI yet.
- Stack: React + Vite, Zod 4, Zustand, idb, Vitest + fast-check, Playwright, Hono on Cloudflare Workers, Workers KV. Hosting: one Worker serving the web build plus `/api`.
- Format decisions: declarative actions only (no scripts). Five object types in the full format (button, field, image, list, ai-field). **No timer or reminder object**: reminders use the `schedule_notification` action. **No icon property**: desktop icons are derived from the stack id. Default card size for new stacks is 512x342, set by `create_stack` in the engine spec.
- The format module now supports the full format: all five object types and all nine actions, with `parseStack`, `serializeStack` and `stackJsonSchema` next to `validateStack`. An unknown object or action type is reported as "is unknown" with code `INVALID_VALUE`; the "not supported in this release" wording is gone. The app is still behind the format: the executor runs only `go_to_card`, `set_value`, `append_item` and `show_message` (it skips the other five with a message), `image` shows a placeholder and `ai-field` is a read-only box.
- Error codes are a closed set of 14. The validator never returns `UNKNOWN_ENTITY` or `OUT_OF_RANGE`; the engine does.
- Slice limits shown honestly in the app: stacks are stored in this browser only, `onOpen` validated but not run, an empty Add appends an empty item (no conditionals).

## 2b. Stack engine (`@hypergeist/shared/engine`)

Public API: `executeHandler`, `applyOperation`, `OPERATION_NAMES`, `OPERATIONS`, `operationJsonSchema`, `buildRenderModel`, `remixStack`, `createStack`, and the types `OperationResult`, `OperationSummary`, `EffectRequest` and friends. All are pure. See the "Stack engine" section of `README.md`.

- **`executeHandler` changed behavior.** The five Actions it used to skip with a "not supported" message are now handled. `remove_item` runs. `run_ai_field`, `fetch_news`, `transcribe_audio` and `schedule_notification` return effect requests as plain data in `effects` (each has `kind` and `actionIndex`). The engine never carries them out.
- **Web store.** `apps/web/src/state/stack-store.ts` turns each effect request into a status message ("... arrives in a later release"). The UI still does not call `applyOperation`, `buildRenderModel` or `createStack`.
- **Seven Operations** (`create_card`, `delete_card`, `add_object`, `update_object`, `remove_object`, `link_cards`, `set_action`). Each result is `{ ok: true, stack, summary }` or `{ ok: false, errors, truncated }`. A rejected call never carries a stack. An accepted call always returns a stack that passes `validateStack`. Deletes cascade: Links, Handler Actions and `inputObjectIds` entries that name a removed entity are removed, and `summary.removedActions` counts the removed Actions.
- **Decisions made during the run.** An omitted required parameter gives `MISSING_PROPERTY` at the parameters root (`""`). Over-long text gives `LIMIT_EXCEEDED`. An unknown parameter gives `UNKNOWN_PROPERTY`. An `id` or `type` key in `update_object.changes` gives `INVALID_VALUE`. An out-of-range `index` gives `OUT_OF_RANGE` at `/index`.
- **Test note.** The closure property (`operations/closure.property.test.ts`) runs up to 50 operations per case. It timed out at 30 s once when the whole suite ran in parallel. It now does less work per step and has a 120 s timeout.
- **E2E:** the Developer ran `pnpm test:e2e` on 2026-11-15: 8 of 8 passed.

## 2c. Local persistence (`apps/web/src/persistence`)

- **Repository.** One `Repository` interface with two implementations: IndexedDB (`idb-repository.ts`, database `hypergeist` v1, stores `stacks`, `trash`, `quarantine`, `meta`) and in memory (`memory-repository.ts`). The shared contract test `repository.contract.ts` runs against both, and a model-based property test checks that they agree. Every read is parsed with `parseStack`; a record that fails is moved unchanged to the quarantine.
- **Boot.** `AppRoot` runs `bootPersistence`: open the repository (IndexedDB, else Memory_Mode with a banner), seed the demo stacks once, pick the last opened stack. Demo stacks are the `.json` files directly in `apps/web/src/stacks/`. A bundled stack that changes later does not update a user who already seeded; "Restore demo stacks" does, and it moves their edited copy to the trash.
- **Autosave.** About 1 second after the last change, one write at a time, the label Saved, Saving or Not saved in the stack window. The Stacks window flushes pending edits before every action (`beforeAction`). Limit: closing a tab right after a change can lose the last second.
- **Stacks window.** Open, export (`<name>-<id>.hypergeist.json`), delete (to the trash), import (5 MB limit, untrusted, never overwrites, copy on id conflict), trash (50 stacks), restore demo stacks. It is deliberately plain. The `retro-ui-shell` spec will turn it into desktop icons and a trash icon on the same repository calls.
- **Tests that needed `fast-check` in `apps/web`.** `fast-check` is now an `apps/web` devDependency, and `check:deps` lets `*.test.ts(x)` files in the apps import `packages/shared/test-support` by relative path. Production code keeps the strict rule.
- **Opening a stack.** The stack store is created once; `replaceStack` loads another stack into it, so the Stacks window stays open after delete and restore demo stacks (found by the Developer's first e2e run, which also caught a wrong path in the new e2e file).
- **Known rough edges.** A write that never settles blocks the Stacks window actions. `onBlocked` cannot fire until the database version goes above 1.
- **Not verified by the Developer yet:** the manual checklist (e2e passed 16 of 16).

## 2d. AI orchestrator (`apps/web/src/ai`)

- **What it is.** Plain TypeScript, no React. `runTurn` takes a provider, the stack, the current card and selection, and a user message. It builds a compact context (under 12,000 characters), asks the model with the tool registry, applies each tool call with `applyOperation`, sends rejected calls back with a short repair message, and returns `TurnResult` (`status` done, partial, failed or aborted; `before` and `after` stacks; steps; say text). `after` is always valid. Limits per Turn: 8 requests, 40 calls, 90 seconds, 6 rejected calls, 2 repair rounds in a row. Public API: `apps/web/src/ai/index.ts`.
- **Decisions.** The hosted key lives on the Worker and is the main path. An own key is optional and kept in memory only. A half-working Turn keeps the accepted changes and the UI offers undo with `before`. Demo prompts match exactly (no fuzzy matching); an unknown prompt gets the list of examples. The demo chain is Worker proxy, then recorded examples, with a plain note on why (`demoNote`). An own key never falls back silently.
- **Tools.** The seven Operations (descriptions and schemas from `OPERATIONS`) plus `say` and `create_stack` (new stacks only). A compact schema profile keeps the tool definitions at 11,514 characters (the full schemas are 26,717) so requests fit free-tier token limits.
- **Provider contract the Worker must implement** (spec `worker-backend`): `POST /api/ai/chat` on the app's origin, OpenAI chat-completions request body in (the `model` field is `auto`; the Worker picks the real model from its allowlist), OpenAI reply out (non-streaming). Failures: HTTP error status with JSON `{ "error": { "code": "RATE_LIMITED" | "DAILY_CAP" | "MODEL_NOT_ALLOWED" | other } }`. The client maps `RATE_LIMITED` to rate limited, `DAILY_CAP` to quota, `MODEL_NOT_ALLOWED` to bad request, anything else or a non-JSON body to server error, and then falls back to the recorded examples. The Worker must never return the hosted key or the upstream error body.
- **Demo scenarios.** JSON files in `apps/web/src/ai/scenarios/` (modes `new-stack`, `edit`, `text`). Two ship now: "Make me a to-do list" and "Add a button" (plus a text scenario for AI fields). The showcase specs add more by adding files.
- **Known gaps.** (1) A model that ignores tools without returning an HTTP error is not detected: the Turn ends `done` with no steps. The UI can start in JSON mode when `detectCapabilities` reports `toolCalling` as `no` or `unknown`; a later task could also accept JSON found in a plain reply. (2) A wrong base URL path returns 404, which is reported as "model not found". (3) The capability cache cannot see a key change from one key to another; the caller must call `clear()`. (4) `usage` from the provider is dropped, so token counts come from the provider dashboard (see the checklist). (5) The first real-provider try-out has not happened.
- **Not verified by the Developer yet:** the real-provider checklist `docs/manual-verification-ai.md`.

## 2e. Worker AI proxy (`apps/worker/src`)

- **Routes.** `POST /api/ai/chat` and `GET /api/ai/quota`, both same-origin only. Pipeline: config, origin, bounded body (128 KB), strict schema (`@hypergeist/shared/ai-wire`), model check, burst limiter (Rate Limiting binding `AI_BURST`, 10 per 60 s per visitor), quota reservation (Durable Object `QuotaStore`), provider loop with failover, token accounting, public reply cut to content, tool calls and finish reason. Every failure is `{ error: { code } }` built only by `lib/errors.ts`.
- **Providers (Developer's decision, 2026-11-15).** Sarvam for development and OpenAI for the submission, in a fixed table (`ai/providers.ts`); configuration, not code. OpenAI uses `max_completion_tokens` and gets no `temperature`; `reasoning_effort` is sent only when `AI_REASONING_EFFORT` is set. The Worker sends no reasoning setting to Sarvam.
- **Limits.** Per visitor per day (60 requests), per day (400 requests, 1,000,000 tokens), lifetime (6,000 requests, 6,000,000 tokens), burst 10 per minute. All are `vars` in `wrangler.jsonc`. Visitors are SHA-256 hashes of IP, UTC date and `QUOTA_SALT`. Fail closed when the counters or the limiter fail. Counts are made when a request is forwarded; tokens are added from the provider's `usage` (or estimated).
- **Secrets** (set by the Developer with `wrangler secret put`, never by an agent): `SARVAM_API_KEY`, `OPENAI_API_KEY`, `QUOTA_SALT`. `.dev.vars` and `.dev.vars.*` (except `.example`) are git-ignored.
- **Switch for the submission.** Set `OPENAI_API_KEY`, set `AI_PROVIDERS=openai` and `AI_OPENAI_MODEL`, optionally `AI_REASONING_EFFORT`, redeploy, run the checks. Also set a hard spending limit in the OpenAI project.
- **Known gaps.** (1) Lifetime counters never reset and `/api/ai/quota` shows only the day's request counts, so test traffic with Sarvam counts against the lifetime caps: set them to the real remaining budget before the submission. (2) Reasoning models can return empty content with `finish_reason: length` when reasoning uses the output budget; the manual checks record the real behavior of the chosen models. (3) Several provider facts (Sarvam accepting `Authorization: Bearer` on `/v2`, `namespace_id` 1001 on a free account, the Rate Limiting binding under `wrangler dev`, whether the dashboard can edit a var that `wrangler.jsonc` defines) were not verified from the code or docs. (4) Two property tests keep a local copy of the seed helper because `packages/shared/test-support/seed.ts` uses `globalThis.crypto`, which the worker's TypeScript setup does not declare.
- **Not done by an agent.** Nothing was deployed and no secret was set or read.
- **Not verified by the Developer yet:** the deployment and `docs/manual-verification-worker.md`.

## 3. Gotchas learned (also in `docs/kiro-journal.md`)

- pnpm 11+ ignores `onlyBuiltDependencies`; use `allowBuilds` in `pnpm-workspace.yaml`.
- TypeScript is pinned to `~6.0.0`. TypeScript 7 lacks the stable JS compiler API that typescript-eslint and `scripts/check-deps` need.
- Quote `'@hypergeist/shared@workspace:*'` in zsh.
- Shared sources and `scripts/` use explicit `.ts` import extensions so Node can run them; a lint rule enforces it. Erasable TypeScript only.
- Vitest globals are off: call `cleanup` in `afterEach` in React tests.
- A CSS scan test fails any `.tsx` file that contains the string `--ghost`.
- Wrangler in the agent sandbox needs `XDG_CONFIG_HOME=/tmp/wrangler-xdg WRANGLER_SEND_METRICS=false`. Chromium cannot open pages in the agent sandbox.
- A Playwright test that presses keys right after `page.goto` can race React; wait for the app first.
- GitHub pushes use a personal access token with `repo` and `workflow` scopes stored in macOS Keychain.

## 4. Open issues and known gaps

- **UI/UX first pass.** The user expects many changes. Known from the design review: touch targets under 24 px (close box, handles), focus ring on inverted items, `--ghost` contrast of 2.57:1 on paper (use it with a shape), "Interact mode: nothing can be edited" wording, trash and Ghost both bottom-right, fixed 512x342 card vs phone widths, font coverage for non-Latin text and emoji, dither of cross-origin images needing a Worker image proxy.
- KV free plan: 1,000 writes per day and eventual consistency; the share spec needs a "busy" path.
- BYO key straight from the browser depends on provider CORS; capability detection needs a connectivity probe.
- The draft tool registry mixes engine operations with names like `fetch_news` that are also stack actions; the orchestrator spec must separate model tools from runtime actions.
- Shared stacks can leak the viewer's IP through `https:` images and can spend the viewer's AI quota through ai-fields.
- Brief open questions still open: hero stack for the demo video, reminder mechanism and its limits, whether to attempt the Kiro Crew bonus.
