# Manual verification: local persistence

Spec: `.kiro/specs/local-persistence` (Requirement 9.4). Do this list in real browsers before submission. The automated tests use a fake database, so they cannot prove how real browsers behave.

## How to use this file

**Browsers.** Test in the current Chrome, Firefox and Safari on desktop (skip one only if you do not have it, and write that in the sign-off). Also test once in a phone-sized window: use the browser's responsive mode, or a real phone.

**Fresh profile.** Where a case says "fresh window", use a new browser profile, or a private window. It must have no HyperGeist data. Do not use the profile you develop in.

**Open the stored data.** In Chrome or Edge: press F12, open **Application**, then **Storage > IndexedDB > `hypergeist`**. In Firefox: open **Storage > Indexed DB**. In Safari: enable the Develop menu first (Settings > Advanced), then open **Storage > Indexed Databases**. The database has four stores:

- `stacks`: one record per stack. The key is the stack id.
- `trash`: deleted stacks. The key is a number.
- `quarantine`: records that could not be read, kept unchanged.
- `meta`: `seeded` (true after the first run) and `lastOpenedId`.

The view does not refresh by itself. Use the refresh button in DevTools after each action.

**Clear site data.** Chrome or Edge: **Application > Storage > Clear site data**. Firefox: **Storage**, right-click the site, **Delete All**. Safari: **Storage**, select the database, delete it. Then reload the page. You can also delete only the database `hypergeist` from the IndexedDB list.

**How to read the cases.**

- "The Stacks button" is the button labelled **Stacks** in the menu bar.
- Write **Pass**, **Fail** or a short note in the Result column. Name the browser if the result differs between browsers.
- The wording in "Expected" comes from the app's code. If the app shows different wording, write that in the Result column.
- A few cases are hard to reproduce by hand. They say so, and give a fallback: the automated test that covers them.
- Run the cases in order inside a group. Each group starts from a fresh window unless it says otherwise.

## 6. Memory_Mode (storage blocked or unavailable)

Memory_Mode is the fallback when the browser will not open its storage. The banner text is exactly: **Changes are lost when you close this page. Export before leaving.**

How to get Memory_Mode, by browser. Try the first way for each browser and write down which way worked.

- **Firefox, private window.** Older Firefox versions block IndexedDB in private windows. Newer versions allow it, so you may not get Memory_Mode here.
- **Firefox, storage turned off.** Open `about:preferences#privacy`, choose **Custom** and block cookies and site data for the site, or set `dom.indexedDB.enabled` to `false` in `about:config`. Reload the app.
- **Chrome or Edge.** Settings > Privacy and security > Third-party cookies or Site settings > **Block third-party cookies and site data**, or **Cookies and site data > Block all cookies**. Add the app's address to the "Not allowed to save data" list. Reload. A private window by itself usually still allows IndexedDB.
- **Safari.** Settings > Privacy > **Block all cookies** (older macOS) or use a private window. Results vary.
- **Any browser.** If you cannot block storage: open the browser console before the page loads and run `Object.defineProperty(window, 'indexedDB', { value: undefined })` through a snippet that runs on load (DevTools **Sources > Snippets** in Chrome). Write "simulated" in the Result column.
